## Decisions this plan makes (flagged for Gal)

| # | Decision | Why |
|---|---|---|
| P1 | Service names `cinecircle-server` (API) and `cinecircle-web` (static), both unclaimed on `onrender.com` when checked; `cinecircle-api` is taken. URLs: `https://cinecircle-server.onrender.com`, `https://cinecircle-web.onrender.com`. Region `frankfurt` for the API (same as the database), plan `free`. | Render's `fromService` only exposes the private hostname, so the public URLs are written into the Blueprint. |
| P2 | Non-secret values are written in `render.yaml`: `APP_ENV=production`, `CORS_ORIGINS`, `SUPABASE_URL`, `VITE_API_URL`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (browser-safe by design). Secrets are `sync: false`, typed once by the owner: `DATABASE_URL`, `TMDB_API_KEY`, `OMDB_API_KEY`. | Fewest manual steps; no secret in git. |
| P3 | `DATABASE_URL` accepts what the Supabase dashboard gives: `postgres://…` and `postgresql://…` are rewritten to `postgresql+psycopg://…`; `postgresql+psycopg://…` is left alone; any other scheme stays as it is. Surrounding whitespace is stripped. | A pasted dashboard URL would otherwise fail at startup (SQLAlchemy would look for psycopg2). The README's "rejected" sentence is updated. |
| P4 | `make_engine` passes `prepare_threshold=None` in `connect_args`, always. README tells the owner to use the **Transaction pooler** string (port 6543). | Supavisor in transaction mode cannot keep server-side prepared statements; psycopg 3 prepares after 5 uses. The app's role and claims are transaction-local, so they work in this mode. Negligible cost on hand-written SQL. |
| P5 | Render settings: API build `pip install uv && uv sync --frozen --no-dev` in `rootDir: api`, start `.venv/bin/uvicorn cinecircle_api.main:create_app --factory --host 0.0.0.0 --port $PORT`, health check `/live`, `PYTHON_VERSION=3.14.6` (the tested version; Render requires a full version). Web: repo root, `npm ci -w web --include=dev && npm -w web run build`, publish `web/dist`, `NODE_VERSION=22`, rewrite `/*` → `/index.html`, headers `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, build filters so each service redeploys only for its own files. | `/live` does not depend on the database, so a database blip doesn't restart the service. No CSP yet (Supabase, TMDB images and Google avatars would need listing; risk of a broken first deploy). |
| P6 | `cinecircle_analysis` stays in the wheel: the app never imports it (unit test), and its CLI refuses unless `APP_ENV=local`. | Removing it needs a second package definition for no user-visible gain. |
| P7 | Web polish from the Phase 6 deferrals, only the three real users see: genre chips in one horizontally scrolling line; chips stay on a failed filtered fetch so the filter can be cleared; a muted "TMDB —" on unrated cards. | The rest (reviews negative cache, unknown-genre refetch, shared rating SQL, StatsPage cosmetics) has no user-visible effect at 5 users. |
| P8 | Render MCP is not added: not available in this environment; Render is driven by the Blueprint. Supabase MCP is already connected. | `04` lists the MCPs as tooling, not product. |

**Conflict check with `00`:** none. No user-data path changes. R5 enforcement depends on the API connecting as a role that can `SET ROLE authenticated`, which the pooler's `postgres` user can (verified on cloud through the MCP session; confirm once more after the first deploy with a sign-in).

## Global Constraints

- Everything in the Phase 0–7 plans' Global Constraints still holds: `ruff` clean (line length 100); keys never in git / `web/` / logs / responses; hidden or missing → 404; every route except `/live` and `/health` requires sign-in.
- **Only the publishable key may appear in the repo or in `web/`.** Never the secret/service key, the database password, a `DATABASE_URL`, or TMDB/OMDb keys.
- Web: no physical `left`/`right` utilities; touch targets ≥ 44 px; **390 px** with no page-level horizontal scroll (a chip row scrolls inside its own container); numbers in `<bdi>`.
- Never overlap two integration runs. Delete local e2e accounts first.

## Review Focus

1. **A password containing URL-special characters survives the rewrite:** only the scheme prefix changes, the rest of the string is byte-identical. → Task 1 `test_database_url_keeps_the_rest_intact`.
2. **An unrelated scheme or a `+psycopg2` URL is not silently rewritten.** → Task 1 `test_database_url_other_schemes_untouched`.
3. **A secret typed into `render.yaml`:** a test fails if any of the three secret keys has a `value:` or if a service-role/secret key pattern appears. → Task 2 `test_blueprint_keeps_secrets_out`.
4. **A deep link or refresh on the static site** (`/titles/4`, `/stats`) must serve the app, not a 404. → Task 2 `test_blueprint_rewrites_to_the_app`.
5. **A failed filtered Discover fetch** leaves the chips usable so the user can clear the genre and recover. → Task 3 `it('keeps the genre chips when a filtered fetch fails')`.
